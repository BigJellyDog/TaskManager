# ТЗ: TaskManager (проект №2 для портфолио)

> Как пользоваться: иди по этапам сверху вниз, закрывай чекбоксы `[ ]` → `[x]`, после каждого этапа делай коммит.
> Стек: C# / .NET 10, .NET MAUI (только Windows), EF Core, SQLite, xUnit.
> **Изменение:** вместо консольного интерфейса (CLI) делаем MAUI-приложение. Пункты про `System.CommandLine`, `Spectre.Console` и консольные команды заменены на экраны MAUI; бизнес-логика (Core, Infrastructure) не меняется.
> Что нового по сравнению с ExpenseTracker: конечные автоматы, графы зависимостей, фоновые сервисы, история изменений, оптимистичная блокировка, паттерн Specification.

---

## 1. Легенда (что "сказал заказчик")

> "Мне нужна программа для задач, которой удобно пользоваться из терминала. Задачи бывают с приоритетом, дедлайном и тегами, и могут иметь подзадачи. Некоторые задачи нельзя начать, пока не сделана другая (например, 'задеплоить' после 'написать тесты'). Повторяющиеся задачи ('оплатить аренду' каждый месяц) должны сами создавать следующую после выполнения. Хочу напоминания о горящих дедлайнах, чтобы программа сама говорила, что пора. И хочу видеть историю: когда и что я менял в задаче. Данные не должны пропадать."

## 2. Функциональные требования

### FR-1. Задачи (CRUD)
- Поля: название (обязательно), описание, приоритет (`Low` / `Medium` / `High` / `Critical`), дедлайн (необязательно), теги, дата создания
- Редактирование любого поля, мягкое удаление (`IsDeleted`), восстановление удалённой задачи
- Валидация: название не пустое и не длиннее 200 символов, дедлайн не в прошлом (только при создании)

### FR-2. Статусы как конечный автомат
- Статусы: `Todo`, `InProgress`, `Blocked`, `Done`, `Cancelled`
- Разрешённые переходы описаны явно (например, `Done → InProgress` разрешён только через "переоткрыть"; `Cancelled → Done` запрещён)
- Недопустимый переход даёт понятную ошибку, а не молча меняет статус
- Таблица переходов лежит в одном месте и покрыта тестами

### FR-3. Подзадачи
- У задачи может быть сколько угодно подзадач, вложенность до 3 уровней
- Родитель нельзя перевести в `Done`, пока не завершены все подзадачи
- Прогресс родителя считается автоматически (`3/5 выполнено`)

### FR-4. Зависимости между задачами
- Задача A может зависеть от задачи B ("A нельзя начать, пока B не `Done`")
- Задача с невыполненной зависимостью автоматически получает статус `Blocked`, а при выполнении зависимости разблокируется
- **Защита от циклов:** A → B → C → A должно отклоняться при добавлении зависимости (поиск цикла в графе)
- Команда показывает дерево зависимостей задачи

### FR-5. Теги
- Связь многие-ко-многим (у задачи много тегов, тег у многих задач)
- Переименование тега затрагивает все задачи
- Удаление неиспользуемых тегов

### FR-6. Поиск, фильтры, сортировка
- Фильтры: статус, приоритет, тег, диапазон дедлайнов, "только просроченные", "на сегодня", "на неделю"
- Полнотекстовый поиск по названию и описанию
- Сортировка по нескольким полям (например, приоритет, затем дедлайн)
- Фильтры комбинируются между собой
- Постраничный вывод (`--page`, `--page-size`)
- Фильтры реализованы через паттерн **Specification** (комбинируемые объекты-условия), а не набор `if` в одном методе

### FR-7. Повторяющиеся задачи
- Правила: ежедневно, еженедельно (с выбором дней недели), ежемесячно, ежегодно
- Режим "после выполнения" и режим "по календарю" (следующая создаётся по расписанию, даже если предыдущая не закрыта)
- Крайние случаи: 31-е число, 29 февраля, смена летнего/зимнего времени
- При завершении создаётся следующая копия: теги и подзадачи копируются, дедлайн сдвигается

### FR-8. Напоминания (фоновый сервис)
- Фоновый сервис (`BackgroundService` / `IHostedService`) запускаемый вместе с приложением, проверяет дедлайны раз в минуту
- Уведомление в приложении за 24 часа, за 1 час и при просрочке; одно и то же напоминание не показывается дважды
- Корректная остановка по `Ctrl+C` (`CancellationToken`)

### FR-9. История изменений (audit log)
- Каждое изменение записывается: что изменилось (поле, старое значение, новое значение), когда, какая команда
- Карточка задачи показывает хронологию задачи
- Запись истории происходит в той же транзакции, что и изменение

### FR-10. Конкурентные изменения
- Оптимистичная блокировка через `RowVersion` / токен конкурентности EF Core
- Если задачу изменили между чтением и сохранением, пользователь получает понятное сообщение и предложение повторить

### FR-11. Статистика
- Выполнено за неделю / месяц
- Процент выполненных вовремя
- Среднее время от создания до выполнения
- Количество просроченных и заблокированных
- Распределение по приоритетам (гистограмма в интерфейсе)

### FR-12. Импорт и экспорт
- Экспорт всех задач в JSON и Markdown (чек-лист с вложенными подзадачами)
- Импорт из JSON с проверкой структуры и отчётом (добавлено / пропущено / ошибки)

### FR-13. Интерфейс (MAUI, Windows)
- Экраны: список задач (фильтры, поиск, сортировка, постраничность), карточка задачи (подзадачи деревом, зависимости, теги, история), создание/редактирование, статистика (гистограмма по приоритетам), импорт/экспорт, настройки
- Действия над задачей: начать, выполнить, переоткрыть, удалить, восстановить, добавить зависимость
- Цвета по приоритету, понятные сообщения об ошибках (недопустимый переход, цикл зависимостей, конфликт версий)
- Напоминания внутри приложения (фоновый сервис, пока приложение открыто)
- Служебные действия: демо-данные (seed), резервная копия БД и восстановление

## 3. Нефункциональные требования

- **Слои:** `Core` (домен и логика), `Infrastructure` (EF Core, файлы), `App` (MAUI), `Tests`
- Домен не зависит от EF Core и от UI; бизнес-правила (переходы статусов, циклы, повторения) живут в `Core`
- Доступ к данным через интерфейсы (`ITaskRepository`, `ITagRepository`), плюс `IUnitOfWork` для транзакций
- Dependency Injection через `MauiProgram` (`builder.Services`), ViewModel'и по MVVM
- Время только через `TimeProvider`
- Все операции с БД асинхронные, с передачей `CancellationToken`
- Конфигурация через `appsettings.json` и `IOptions<T>` (путь к БД, интервал напоминаний, размер страницы)
- Логирование через `ILogger` + Serilog
- `<Nullable>enable</Nullable>`, `.editorconfig`, `.gitignore`, анализаторы (`TreatWarningsAsErrors` для Core)
- Тесты: xUnit; логика на `FakeTimeProvider`; репозитории на SQLite in-memory; покрытие ключевой логики не менее 80%
